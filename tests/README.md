# Тестовое окружение

Всё, что проверяет библиотеку, лежит здесь и в сборку стороннего проекта не попадает.
`INCLUDE/` и `SRC/` — это только сама библиотека.

| Что | Где | Чем запускается |
|---|---|---|
| Юнит-тесты (gtest) | `*_test.cpp` | `build\clang-release\seraph_tests.exe` |
| Нативы-фикстуры | [plugins/](plugins/) | собираются в два плагина |
| Скриптовая сьюта | [mod/SIXW_GRAFT/](mod/SIXW_GRAFT/) | dayz-mcp `run_suites(["seraph::graft"])` |

## Юнит-тесты

Без игры и без движка: `scan_test` гоняет сканер по синтетическому образу,
`proto_test` — генерацию объявлений, `types_test` — соответствие типов и раскладку,
`plugins_test` — логику загрузчика (разбор `-mod=`, сверка версий, слияние реестров и
коллизии), `ping_test` — домен фикстуры.

`callout_test` — вызов В ДРУГУЮ СТОРОНУ (движковые `proto` из C++) против ФАЛЬШИВОГО
движка: дескриптор функции и дескрипторы её параметров, разложенные ровно по
`graft::layout`, плюс импл — обычная C-функция. Так вся сборка блока аргументов
проверяется без игры, включая обе формы вызова (с объектом в rcx и без него).

`runtime_test` — то, что раньше проверялось только в игре, а теперь и без неё: арена
возвращаемых строк, состояние загрузчика (тики и корень), значения любого скриптового
типа, модель памяти, оставшиеся пути отказа маршалируемого вызова.

`enfparse_test` — разбор объявлений Enforce и зеркало движкового API. Все строки в нём
взяты из ванильных скриптов как есть: если разбор их не осилит, зеркало будет молча
неполным, а узнать об этом на живом сервере дороже всего. Там же — модель памяти
скриптовых типов: `Managed`, сущности мира, приватные конструктор и деструктор.

## Покрытие

```
coverage.bat          :: цифры
coverage.bat show     :: html с построчной раскраской
```

**75.7% по строкам** на момент последнего замера — и это потолок для оффлайнового
измерения, а не лень. Половина библиотеки исполняется ТОЛЬКО внутри игры: трамплины
зовёт движок (`marshal.hpp`, `dispatch.hpp`), доступ к script-контекстам требует его
указателей (`script_host.cpp` — 10%), журнал пишется рядом с exe (`log_host.cpp` — 0%).
Никакой llvm-cov этого не увидит; это покрывает сьюта `seraph::graft`.

Что удалось поднять оффлайн: `loader_state.cpp` 0 -> **100%**, `text.cpp` 50 -> **86%**,
`world.hpp` 64 -> **85%**, `callout.hpp` 58 -> **72%**, `types.hpp` 66 -> **73%**.

## Плагины-фикстуры

| Плагин | Исходник | Роль |
|---|---|---|
| `SIXW_GRAFT` | [plugins/natives.cpp](plugins/natives.cpp) | матрица покрытия ABI: по нативу на каждый поддерживаемый тип |
| `EXAMPLE_HASHMAP` | [../examples/hashmap/src/cpp_hashmap.cpp](../examples/hashmap/src/cpp_hashmap.cpp) | шаблонный скриптовый класс `CppHashMap<K,V>` поверх `std::unordered_map` |

Плагина именно **два**, и это не деление по смыслу: сьюта гоняет оба в одном процессе,
поэтому «два плагина уживаются» проверяется обычным прогоном, а не отдельным ритуалом,
который забудут запустить. Сломается сосуществование — покраснеет половина кейсов.

Второй живёт в [../examples/hashmap/](../examples/hashmap/) и оттуда же собирается корневым
`CMakeLists.txt`: он и пример, и фикстура, копии исходника нет. Пример без тестов быстро
расходится с кодом — этот не может.

Часть нативов намеренно написана обычным C++ (`int`, `std::string_view`, `std::string`,
`std::vector`, `std::array<float,3>`, неконстантная ссылка вместо `out`), часть — в
типах библиотеки. Так живым вызовом проверяются обе формы, а не только та, что удобнее.

## Скриптовая сьюта

`mod/SIXW_GRAFT` — **junction** на `E:\DayZ\PDrive\SIXW_GRAFT`: моды экосистемы живут
под `P:\`, а dzrun жёстко пропускает reparse-точки, поэтому исходник мода должен быть
реальным каталогом там. Правится он в любом из двух путей — это одни и те же файлы.

Внутри 86 кейсов:

- матрица ABI — по кейсу на тип, поля объектов, движковые методы, контейнеры, `out`;
- `Manager_*` — два плагина в одном процессе, версии хоста, ноль коллизий;
- `Out_*` — вызов В ДРУГУЮ СТОРОНУ: чтение дескриптора, маршалируемый `proto` движка,
  `typename.Spawn`, поле через `GetClassVar`, целевой сценарий «игроки и их steam id»;
- `Tick_*` — точка входа для C++ и корень объектного графа;
- `Field_*` — прокси поля в стиле sol2 против явной формы;
- `Perf_HotPathBudget` — вентиль скорости: цена вызова в единицах ванильного натива.
  Меряет минимумом из шести раундов и сравнивает ОТНОШЕНИЕ к `map.Count()`:
  миллисекунды плавают на ±30%, отношение — нет.

Объявления `scripts/<модуль>/grafted_natives_*.c` генерируются сборкой (`graft protogen`,
POST_BUILD) — править руками нечего.

Регистрация в песочнице MCP: `dayz-mcp.config.json → utest.sandboxPbos.client +=
"SIXW_GRAFT"`.

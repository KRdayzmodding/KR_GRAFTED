# Примеры

| Пример | Что показывает |
|---|---|
| [minimal/](minimal/) | шаблон своего плагина: несколько нативов, PBO, сборка одним `graft_plugin()` |
| [hashmap/](hashmap/) | шаблонный скриптовый класс: `CppHashMap<K,V>` поверх обычного `std::unordered_map` |
| [players/](players/) | обратное направление: C++ сам ходит в игру — тик, зеркало движкового API, сбор игроков и их steam id |

Каждый пример — **самостоятельный проект**: копируешь каталог куда угодно и указываешь
путь к библиотеке.

```bat
graft new MYMOD E:\source          :: развернуть шаблон под своим именем
cmake -B build -DGRAFT_ROOT=E:/source/KR_GRAFT
```

## Примеры покрупнее живут в самом репозитории

Основной плагин репозитория — это тоже пример, просто с тестами:

| Плагин | Исходник | Что в нём |
|---|---|---|
| `SIXW_GRAFT` | [../tests/plugins/natives.cpp](../tests/plugins/natives.cpp) | матрица покрытия ABI: по нативу на каждый поддерживаемый тип, поля объектов, движковые методы, `std::ranges` по скриптовым данным |

Он лежит в [../tests/plugins/](../tests/plugins/), а не здесь, по простой причине: его гоняет сьюта
`seraph::graft`, а в примерах свой сервер не поднимается. Пример без тестов быстро
расходится с кодом, а этот не может — он собирается и проверяется каждой сборкой.

По той же причине [hashmap/](hashmap/) собирается ДВАЖДЫ: сам по себе как пример и вторым
плагином корневого `CMakeLists.txt`. Так сьюта гоняет два плагина в одном процессе, и
«два плагина уживаются» краснеет обычным прогоном — а пример при этом не копия, а тот
же самый файл.

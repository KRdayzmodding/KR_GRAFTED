# Примеры

| Пример | Что показывает |
|---|---|
| [hello/](hello/) | hello world: одна функция C++, один вызов из скрипта, весь цикл разработки |
| [minimal/](minimal/) | шаблон своего плагина: несколько нативов, PBO, сборка одним `graft_plugin()` |
| [hashmap/](hashmap/) | шаблонный скриптовый класс: `CppHashMap<K,V>` поверх обычного `std::unordered_map` |
| [players/](players/) | обратное направление: C++ сам ходит в игру — тик, зеркало движкового API, сбор игроков и их steam id |

Каждый пример — **самостоятельный проект**: копируешь каталог куда угодно и указываешь
путь к библиотеке.

```bat
graft new MYMOD C:\src                 :: развернуть шаблон под своим именем
cmake -B build -G Ninja                :: graft подтянется сам (graft_import)
cmake --build build                    :: MYMOD.grafted.dll + MYMOD.scripts в build/
```

## Примеры и тесты не пересекаются

Матрица покрытия ABI — по нативу на каждый поддерживаемый тип, поля объектов, движковые
методы, `std::ranges` по скриптовым данным — живёт в [../tests/plugins/](../tests/plugins/)
и примером не является: её гоняет сьюта `seraph::graft`, а в примерах свой сервер не
поднимается.

Раньше пример [hashmap/](hashmap/) собирался ВТОРОЙ раз корневым `CMakeLists.txt` и
работал вторым плагином фикстуры. Так пример не мог сгнить — но и меняться свободно
тоже: правка примера роняла сьюту. Теперь у тестов свой второй плагин, а примеры
собираются только своими проектами. Что они не сгнили, проверяет таргет `examples` —
он собирает каждый ровно так, как его собирает пользователь (ExternalProject, отдельное
конфигурирование), и любая правка публичного API, которая ломает пример, красит сборку.

## Собрать всё разом

```bat
cmake --build --preset examples   :: собрать все примеры, каждый своим проектом
```

У каждого рядом с DLL появляется каталог `<ИМЯ>.scripts` с объявлениями. PBO и папки
`@МОД` собираешь сам — проект в это не лезет.

Каждый пример — отдельный мод: свой `mod/<ИМЯ>/` в исходниках и свой
`<ИМЯ>.grafted.dll` со своим `<ИМЯ>.scripts` в сборке. Как их разложить по `@МОД`
и упаковать в PBO — решаешь ты; graft в это не лезет.

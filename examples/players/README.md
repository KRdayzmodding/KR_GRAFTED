# players — C++ ходит в игру

Второй пример показывает **обратное направление**: не «скрипт зовёт C++», а «C++ сам
работает с игрой». Раз в пять секунд плагин обходит игроков, читает их steam id, имя и
позицию, кладёт в обычный `std::map` — и отдаёт наружу нативом.

**На стороне скрипта нет ничего.** Ни строки: ни `modded class`, ни объявления, ни
вызова. Кадр библиотека берёт сама, подменяя ванильный `CGame.IsServer()` — движок зовёт
его каждый кадр из обновления миссии, — и корень объектного графа приезжает вместе с ним,
прямо в `rcx`. Подробности в README, раздел «Точка входа».

## Что тут показано

| Приём | Зачем |
|---|---|
| `GRAFT_ON_TICK(dt) { ... }` | точка входа: C++ просыпается на скриптовом потоке |
| `graft::game()` | корень объектного графа, тот же `GetGame()` |
| `graft::dayz::CGame` и прочие | зеркало движкового API: настоящие методы с сигнатурами |
| `graft::scratch<graft::array<Man>>()` | буфер под `out`-аргумент движка, один на процесс |
| `game["m_DebugMonitorEnabled"_f]` | поле объекта как lvalue, имя живёт в типе |
| `id.GetPlainId()` | маршалируемый `proto` — путь выбирает библиотека, снаружи разницы нет |

## Сборка

Сперва зеркало движкового API (один раз, и заново после патча игры):

```
graft apigen E:/DayZ/PDrive/scripts src/graft/dayz
```

Дефайны игры ему **не нужны**: он печатает объединение всех веток препроцессора, а чего
в конкретной сборке нет — то не найдётся в рантайме и вернёт нулевое значение со строкой
в `graft.log`. Стоит это ровно столько же, сколько обычный переход в натив.

```
build.bat            :: собрать
build.bat deploy     :: и положить в <игра>\graft\
```

Хост (`dwmapi.dll`) ставится один раз на игру: `graft install <каталог игры>`.

## Чего в примере намеренно нет

**Ссылок на игровые объекты между тиками.** Объект, пришедший от движка, живёт до конца
текущего вызова: движок волен его удалить, а память переиспользовать. Поэтому в
`player_row` лежат ЗНАЧЕНИЯ — строка и позиция, — а не `ref<"Man">`. Если ссылку всё же
нужно пронести, для этого есть `graft::borrowed<T>`: он помнит класс объекта и ловит
переиспользованный адрес.

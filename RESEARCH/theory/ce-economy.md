# Central Economy: карта подсистемы и путь к живому reload экономики

Всё ниже снято с **DayZServer_x64 1.30.164200.56 (retail)** офлайн-сканом образа:
якоря — имена файлов экономики и XML-теги (`types.xml`, `nominal`, `restock`,
`quantmin`, …) — `lea reg,[rip+строка]` из `.text`, границы функций по `.pdata`.
Адреса относятся к этой сборке и живут здесь как указатели на местность, а не как
паттерны: паттерн для плагина — строка-якорь плюс сигнатура пролога, найденного
по ней (см. `scan.hpp`).

## Зачем

Задача — перечитать файлы экономики (`types.xml` и соседей) на работающем
сервере, без рестарта: движкового API для этого нет, путь один — найти загрузчик
и позвать его повторно через graft. Эта карта — первый этап: где что лежит.

## Что нашлось

### Парсеры (компактный модуль, ~0x1408fb000)

| Адрес | Размер | Якоря | Роль |
|---|---|---|---|
| `0x1408fb1b0` | 0x5e | — | диспетчер файла (вызывает парсер types.xml) |
| `0x1408fbda0` | 0x3e0 | types.xml | парсер файла: цикл по `<type>` |
| `0x1408fb6a0` | 0x52a | nominal, restock | парсер одного `<type>` |
| `0x1408fcf89` | 0x2c7 | nominal, quantmin, restock | парсер полей типа |

`cfgspawnabletypes`/`cfgrandompresets` живут рядом (парсер полей `0x1406bd3a0`,
0x839, зовут `0x1406b7910` и `0x1406b8e50`), `cfgeconomycore.xml` парсит
`0x1406a8e20` (0x11a5).

### Список файлов по умолчанию — не в CE, а в аддоне

Функция `0x140a93a20` (нашлась по якорю `types.xml`) — это **конструктор объекта
аддона**: таблицы по RTTI — `enf::Item` (+`BaseItem` в базе), `enf::ClassContainer`
и `DayZAddonManager`. Она регистрирует восемь файлов по умолчанию — `types.xml`,
`globals.xml`, `economy.xml`, `messages.xml`, `events.xml`, `cfgspawnabletypes.xml`,
`cfgrandompresets.xml` (+ ещё один при +0x108) — в полях `this+0x108..0x168` и
ставит `[this+0x100] = 0x7d0` (2000). Единственный вызывающий — `0x1409b9020`
(0x576): создание аддона на старте. Вывод: список файлов экономики — свойство
аддона (миссии), CE берёт его оттуда; правки «какие файлы читать» живут в аддоне,
а не в CE.

### Классы по RTTI

`CentralHive`, `CentralHiveClass`, `CentralHiveClassRegistrator`; `AddonManager@enf`,
`CAddon@enf`, `DayZAddonManager`. Отдельного класса «Economy» нет — экономика,
по-видимому, живёт внутри CentralHive (как и persistence).

## Открытые вопросы (следующие шаги)

1. Кто зовёт диспетчер `0x1408fb1b0` — там цикл загрузки всех файлов; его
   владелец и есть вход для повторного вызова.
2. Контекст вызова: CE-объект (CentralHive?), путь/аддон — вытащить сигнатуры.
3. Поведение при повторной загрузке: счётчики `types.bin`, удалённые типы,
   утечки. Проверять только на стенде: вызов без ответов на эти вопросы — риск
   сегфолта, см. `crashes.md`.

# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [semver](https://semver.org/lang/ru/).

До `1.0` ломающие изменения выходят в **минорной** версии.

Каждый релиз обязан нести две строки: **сборка DayZ, на которой проверено**, и **версии
ABI**. Плагин, собранный под другой `ABI`, хост не загрузит — это не сюрприз, это
проверка в `SRC/graft/plugins.cpp`.

## [Unreleased]

Проверено на: —
ABI: 7, LAYOUT: 2

### Исправлено

- **`ref::call<vector>` падал на обычных нативах объекта** — `GetPosition`, `GetDirection`,
  `GetOrientation`, `GetBonePositionWS` и всех прочих `proto native` без `external`:
  `0xC0000005` внутри движка, порча стека, падение сервера. Возврат больше 8 байт едет
  через скрытый буфер, а натив бывает собран двумя способами: обычный метод — функцией-членом
  C++ (буфер после `this`), `external` — свободной функцией (буфер первым). Библиотека
  звала всё вторым способом, потому что правило было выведено с одного образца —
  `IEntity.GetOrigin`, а он как раз `external`. Теперь `ref::call`/`try_call` (а с ними
  и сгенерированное зеркало) выбирают форму по биту `0x4000` дескриптора — тому же, по
  которому выбирает движок (снято в игре: `Object.GetPosition` `0xa28`,
  `IEntity.GetOrigin` `0x4a28`). Кейсы `NativeCall.*` и `Entity_VectorNativesFromCpp`.
  Обход через `scan::member_call` по `find_method(...).impl` больше не нужен.
- **Свой метод класса с возвратом `vector` ронял сервер.** Та же путаница с обратной
  стороны: флаги наших членов `0xa28` — как у `Object.GetPosition`, и движок зовёт их
  как функцию-член, а трамплин принимал буфер первым и отдавал результат поверх шапки
  скриптового объекта. Трамплин метода с таким возвратом теперь принимает
  `(объект, буфер, аргументы...)`. Кейсы `MemberVectorNative.*` и
  `Fields_VectorThroughPointer` — последний до правки ронял сервер.

## [0.2.0] — 2026-09-28

Доступ к коду движка. Плагин дотягивается туда, где натива нет: находит функцию по
строке-маяку, RTTI или сигнатуре, сверяет её с листингом из отладчика и ставит врезку
сервисом хоста — без единого зашитого адреса, после патча игры сверяется листинг, а не
число. И мод переживает отсутствие своей `.grafted.dll`: на каждый загруженный плагин хост
кладёт дефайн `GRAFTED_<ИМЯ>`.

Проверено на: **DayZ 1.29.0.163709** — пока только `DayZDiag_x64` (сервер и клиент)
ABI: 7, LAYOUT: 2

**Плагины надо пересобрать.** `GRAFT_ABI_VERSION` вырос до 7 — хост отклонит плагин,
собранный под прежний интерфейс. Правок в исходниках мода это не требует: таблица
сервисов только дополнилась.

### Добавлено

- **Дефайн на каждый загруженный плагин: `#ifdef GRAFTED_<ИМЯ>`** (и `GRAFTED` — сам
  хост). Мод получает то, чего у него не было: возможность пережить отсутствие `.grafted.dll`.
  Имя класса в `CfgMods` дефайном становится и без нас — но оно означает «PBO подключён»,
  а про DLL не знает ничего, и сегодня забытая рядом с PBO библиотека роняет компиляцию
  мода целиком на нерезолвнутом `proto native`. Имя — из `GRAFT_PLUGIN("ИМЯ", ...)` как
  есть, символы вне `[A-Za-z0-9_]` становятся `_`: плагин `my-mod 2` даёт `GRAFTED_my_mod_2`.

  Дефайны кладутся в разбор `CfgMods` — единственный механизм, который есть во ВСЕХ
  сборках игры: ключ `-scrDef=` живёт только в `DayZDiag_x64.exe`, в розничных клиенте и
  сервере строки `scrDef` нет вовсе. Обе движковые точки ищутся по форме тела от
  строки-маяка, без единого зашитого адреса (`SRC/graft/defines.cpp`); двусмысленность —
  отказ с записью в журнал, а не врезка в угаданное место.

  `graft protogen` оборачивает файл объявлений плагина целиком в `#ifdef GRAFTED_<ИМЯ>`
  (объявления хоста — в `#ifdef GRAFTED`) тем же правилом имени, по которому хост кладёт
  дефайн. Кроме `1_Core`: этот модуль компилируется без дефайнов вообще (на сервере не
  видны ни `DIAG`, ни имя мода), и обёртка прятала бы там объявления всегда. Плагин
  собирается заново и при смене одного `graft.exe` — иначе `.scripts` оставались бы в
  старом виде.
- **Имена аргументов и описание в объявлениях.** Привязка принимает имена строкой через
  запятую и описание, и `graft protogen` печатает их в `grafted_natives_*.c`:

  ```cpp
  bind.global<&Resettle>("Resettle", "slot, zone, player", "Переселить игрока в зону.");
  ```

  ```c
  // Переселить игрока в зону.
  proto native bool Resettle(int slot, string zone, Class player);
  ```

  То же у `method` и `static_method`. Описание в несколько строк остаётся комментарием:
  `\n` — перенос, пустая строка — `//`. Оба параметра необязательны — без них `p0`, `p1`
  и объявление без комментария, как раньше. Для этого у `graft_native_desc` появились поля
  `param_names` и `doc`: это первый из двух бампов ABI в этом релизе (5 → 6).
- **`graft::value` в глобальном нативе и рядом с обычными типами.** Ванильная идиома
  «любой тип» (`proto void Print(void var)`) раньше работала только в методах класса.
  Теперь её принимают глобальный натив и `static_method`, и в одной сигнатуре с точными
  типами — «любой» ровно там, где нужен:

  ```cpp
  bool Store(graft::i32 slot, graft::obj owner, graft::vec3 at, graft::value payload);
  ```

  ```c
  proto bool Store(int p0, Class p1, vector p2, void p3);
  ```

  Такой натив объявляется `proto`, а не `proto native`: форма вызова у него другая
  (аргументы блоком с тегами), и библиотека выбирает её сама по сигнатуре.
  `out`-аргументы в этой форме — по-прежнему только `graft::value`.
- **`graft::fresh` — новый скриптовый класс из C++.** `bind.class_<T>("Имя", graft::fresh)`
  печатает объявление целиком — `class Имя`, а не правку существующего `modded class Имя`,
  — и объявлять класс в скрипте самому больше не нужно. Раньше так умели только шаблонные
  классы, по `<` в имени; признаком «класс наш» стал явный тег, а не угловая скобка.
- **`graft::hook(target, detour, &orig)` и `graft::unhook(target)`** — врезка в чужой код
  сервисом хоста. Механика врезки в graft была и раньше, но приватная: плагину с
  перехватом приходилось везти свою копию. В процессе она теперь ровно одна, и это не
  удобство: две друг о друге не знают, и вторая перепишет пролог, в котором уже стоит
  чужой переход. Повторная врезка в занятую цель — честный отказ; список занятых целей
  ведёт сам хост.
- **`graft/scan.hpp` доступен плагину.** Разбор образа переехал из `graft_host` в
  `graft_common`: это чистые байты, состояния движка ему не нужно. Плагин ищет свои точки
  в движке тем же кодом, что и хост; секции загруженного образа — `scan::sections_of`.
- **Функция движка по строке: `scan::function_referencing(секции, "текст")`.** Для кода,
  у которого есть строка (текст ассерта, формат журнала), но нет натива: начало функции,
  которая берёт адрес ровно этой C-строки (`lea reg,[rip+строка]`). Ноль — не нашлось или
  на строку ссылаются РАЗНЫЕ функции: угадывать из двух нельзя. Под ней —
  `scan::rip_refs(секции, "текст", insn)`, все места, где инструкция вида `insn` смотрит на
  строку через `rip`, и `scan::function_start(ea)`, начало функции по `.pdata` через
  сцепленные записи раскрутки. Рядом `scan::is_code(p)` — исполняемая ли страница, и
  `view::rel32_after` / `rel32_before(ea, окно, опкод)` — цели переходов с любым опкодом
  (`calls_after` / `calls_before` — их частный случай с `call`).
- **`scan::rtti_vtable(модуль, ".?AVFoo@@")`** — таблица класса по имени из RTTI MSVC.
  Так берётся невиртуальный метод движка, у которого нет своей строки-маяка.
- **`scan::vtable_slots(vt)`** — длина C++ таблицы (подряд идущие адреса кода, с проверкой
  читаемости страницы). Была внутри `objects.cpp`, наружу не торчала.
- **`graft::hook_all({...})` и `graft::hooked(...)`** — врезка пачкой. Не быстрее
  поштучной установки и не ради этого: пачка ставится ЦЕЛИКОМ либо не ставится вовсе.
  Половина врезок — это состояние, в котором мод уже сломан, но ещё считает себя живым.
- **Сигнатура — строкой из отладчика, и она одна на все случаи:
  `scan::sig<"48 8B 81 [disp32]">`.** Разбирается на компиляции, поэтому опечатка в ней —
  ошибка сборки, а не поиск, который молча ничего не находит. Токены: байт как есть,
  `??` — любой (там регистр или смещение, которое сверять нечем), `[disp32]` — ДЫРКА:
  столько бит любых, и это ОТВЕТ. Слово в скобках для читателя, парсер берёт из него только
  число, и оно — ширина в битах: `[disp32]`, `[imm32]` и `[32]` значат одно и то же,
  `[disp8]` — дырка в байт. Четвёртый вид — байт по маске, `05&C7`, — ниже.

  Сверяет `scan::matches(ea, sig)`, ищет в окне и отдаёт дырку
  `scan::find(ea, окно, sig, nth) -> optional<found{site, value}>`. Этим закрыты пять
  прежних способов написать одно и то же: `begins_with` (сверка без джокеров),
  `matches` списком `int`, `matches` строкой, `disp32_of` и `disp8_of` с out-параметрами.
  Все пять не выпускались ни разу — ломать нечего.

  Разница не косметическая. Ширину смещения держало ИМЯ функции (`disp8_of` против
  `disp32_of`), а какая нужна — комментарий рядом с опкодом: два места, которые обязаны
  совпасть, и расхождения не заметил бы ни компилятор, ни тест — код прочитал бы четыре
  байта там, где лежит один, и получил начало следующей инструкции в старших разрядах.
  Теперь ширина написана в сигнатуре один раз, ровно там, где её печатает отладчик.
  Заодно дырка читается СО ЗНАКОМ, как её понимает процессор (`disp8` `0x80` — это −128):
  прежний `disp8_of` расширял нулями и молча превращал её в +128.

- **Сигнатура пишется СТРОЧКАМИ АССЕМБЛЕРА: `scan::code` и `graft/asm.hpp`.** Кодировщик
  x86-64 на `consteval` — байт в байт, на компиляции:

  ```cpp
  constexpr auto prologue = scan::code<R"(
      mov  [rsp+8],rbx
      push rdi
      sub  rsp,20h
      mov  rbx,rcx
  )">;
  constexpr auto field = scan::code<"mov rax,[rcx+disp32]">;
  ```

  Зачем: работа после патча игры — открыть функцию в IDA и сравнить её листинг с исходником
  строка в строку. Шестнадцатеричная простыня такого сравнения не выдерживает, в ней не видно
  даже, где кончается одна инструкция и начинается другая.

  Кодировщик подключается отдельно — `#include "graft/asm.hpp"`: `scan.hpp` его не тянет.
  Как привязаться к функции движка целиком — от строки-маяка через сверку листингом и
  смещение из дырки до врезки — в [README](README.md#привязка-к-ассемблерному-коду).

  **`db` — сырые байты, и он обязателен**, потому что строчка ассемблера байты НЕ определяет
  однозначно. Два живых случая: `push rbp` бывает `55`, а бывает `40 55` — с лишним префиксом
  REX, который MSVC пишет в кадровых функциях; и сигнатура может намеренно ОБРЫВАТЬСЯ посреди
  инструкции — в `mov rbx,[rcx+2B8h]` сверяются первые четыре байта, потому что `2B8h` как
  раз и сдвигает патч игры. Притворяться, что мнемоника это выражает, нельзя.

  Кодировщик знает ровно то, что встречается в разобранных функциях движка. Незнакомая
  инструкция или форма (16-битные операнды, адресация с индексом, две дырки) — **ошибка
  сборки с текстом**, а не молча неверный байт: вся затея ради того, чтобы сигнатуры не
  врали, и догадка в кодировщике обесценила бы её целиком.

  Механика кодирования сверяется с байтами дизассемблера в `tests/asm_test.cpp` — на
  компиляции, поэтому ошибка в кодировщике краснеет сборкой, а не выездом на стенд.

  **На этот подход переведён весь проект.** Рукописных циклов по байтам не осталось ни
  одного:

  | Где | Было | Стало |
  |---|---|---|
  | `SRC/graft/defines.cpp` | `find_rip_lea` — свой цикл по секции | `scan::code<"lea reg64,[rip+disp32]">` + `view::find_rip` |
  | `SRC/graft/defines.cpp` | `shape_of` — три сверки байт в одном цикле | три `view::find` по сигнатурам |
  | `SRC/graft/scan.cpp` | `view::find_lea` — опкод тремя байтами | `view::find_rip`: сигнатура целиком, с дыркой |
  | `SRC/graft/scan.cpp` | `find_frame_entry` — `cvtss2sd` и кэш индекса байтами | сигнатуры + дырка вместо ручной rip-арифметики |

- **Маска в сигнатуре: `05&C7` и `reg64`.** Байт сверяется по маске, а `??` — это её нулевое
  значение. Нужно там, где регистр-приёмник выбрал компилятор игры, а форма адресации
  сверяться обязана: целиком байт `modrm` не сверить, а целиком отпустить нельзя тем более —
  под джокер подойдёт другая адресация, а проверяем мы именно её. В строчках ассемблера это
  `reg64` на месте операнда, в байтовой записи — `05&C7`.

  `reg32` и `reg8` — намеренно ошибка сборки: без `REX.W` у `r8d..r15d` префикс появляется, у
  `eax..edi` нет, и ДЛИНА инструкции разная; одной сигнатурой оба случая не накрыть.

- **`view::find_rip(insn, target)`** — адрес инструкции, которая через `rip` ссылается на
  `target` (`lea reg,[rip+d]`, `mov [rip+d],reg` — любая). Сигнатура берётся целиком, вместе с
  дыркой: `rip` смотрит за конец инструкции, поэтому нужна и её длина. Одна реализация на
  проект; до неё такой цикл был написан дважды, в `scan.cpp` и в `defines.cpp`, и второй
  терял половину регистров (см. «Исправлено»).

- **`view::find(ea, окно, sig)`** — поиск по байтам самой секции, без вопроса системе, цела ли
  страница. У секции байты уже есть, а `base` у неё бывает синтетическим (так собраны фикстуры
  сьюты) — свободная `scan::find` на таком честно отвечает «адрес не читается». Обе первые
  попытки перевода спутали эти две функции, и оба раза поймала сьюта.
- **`scan::readable(p, n)`** — отображены ли байты по адресу. Выравнивания НЕ требует, в
  отличие от `script::detail::readable` (тот сперва спрашивает «похоже ли это на
  указатель», включая кратность восьми): для значения поля это правильно, для адреса
  внутри функции — нет. Проверка страницы теперь одна на библиотеку, а не две копии.
- **`scan::rel32_targets(секции, ea, окно, опкод)`** — цели всех `call`/`jmp` в окне,
  мусорные отброшены. `calls_after` / `calls_before` — его частный случай.
- **`scan::member_call<R>(fn, self, ...)`** — вызов НАСТОЯЩЕГО метода C++ движка. Отличие
  от натива одно и смертельное: скрытый буфер под возврат больше 8 байт у функции-члена
  идёт ВТОРЫМ, после `this`, а у свободной — первым. Перепутанные регистры значат запись
  результата поверх чужого объекта; теперь это правило держит тест, а не память.
- **`graft::position(сущность)` / `try_position`** — позиция объекта мира (`IEntity.GetOrigin`).
  Рядом разобран импл из самого движка: у зарегистрированного натива буфер возврата едет
  ПЕРВЫМ, объект — вторым, и путать эти два случая нельзя.

- **`vector` в поле объекта и в контейнере.** Поле-вектор теперь можно и читать, и
  писать (`set_field`, `["m_pos"_f] =`) — движок за ним ссылок не считает, буфер
  принадлежит объекту. `array<vector>`/`set<vector>` стали элементом наравне с
  `int`/`float`, включая `std::span<const vector>` без копии. Шаг элемента в контейнере
  ВЗЯТ равным 12 байтам по аналогии с числами, а не замерен: замер делает кейс
  `Array_VectorElementStride`, и до его первого зелёного прогона это допущение.

- **Справочник [docs/engine-access.md](docs/engine-access.md)** — поиск (`scan.hpp`),
  врезка (`engine.hpp`) и вход в объектный граф (`world.hpp`) одним документом: сигнатуры,
  ловушки, цена по замерам самой сьюты и сквозной пример от имени класса до вызова метода.

### Изменено

- **Отказ плагину объясняет, что, где и почему разошлось.** Вместо «другая версия
  интерфейса» журнал хоста, `GraftPluginAt` и `graft doctor` пишут имя и версию плагина,
  путь к DLL, оба числа (плагина и хоста) по каждому разошедшемуся — ABI и LAYOUT сразу, —
  у кого они старее и что делать: «пересобрать плагин» или «обновить хост (graft install)».

  Для этого заголовок `graft_plugin_info` (`size`, `abi`, `layout`, `name`, `version`)
  **заморожен** и заполняется плагином ДО сверки — в том числе когда тот отказывает хосту.
  Раскладка структур не изменилась, ABI остаётся 7. Плагин, собранный до этой правки, при
  отказе своих чисел не сообщит: хост так и скажет, назовёт его по имени файла и свои числа.
- **Механика врезки — safetyhook и Zydis вместо MinHook.** Причина: HDE64 внутри MinHook
  не знает VEX/EVEX и на таком прологе отказывает; Zydis знает набор команд целиком.
  Публичный API (`graft::hook`, `unhook`, `hook_all`, `hooked`) и таблица сервисов не
  изменились — пересобирать плагины из-за этого не нужно.

  **Врезка перестала быть дорогой.** MinHook на каждую врезку останавливал все потоки
  процесса, а список брал снимком toolhelp по всей системе: 80 мс на врезку со снятием.
  safetyhook потоки не морозит — он снимает права со страницы и ловит тех, кто по ней
  исполняется, своим векторным обработчиком. Стало 0.03 мс, в две с половиной тысячи раз
  дешевле. Правило «врезку — на старте» при этом осталось, но теперь это контракт, а не
  цена: врезку ставят до того, как движок создаст свои потоки (почему — в
  [docs/engine-access.md](docs/engine-access.md), «Когда врезка безопасна»). Чередовать
  врезку со снятием на живой цели нельзя; это показывает стресс-кейс
  `Hook.TargetUnderTrafficSurvivesInstallAndRemoval`.

  Заодно `hook_all` перестала быть про экономию: заморозки, которую она делила на всю
  пачку, больше нет. Осталось единственное, ради чего её теперь держат, — пачка встаёт
  целиком либо не встаёт вовсе.

  **Что это меняет для обработки сбоев.** Обращение к недоступной памяти стало в этом
  процессе штатным и частым событием: так работает окно патча. Кода в `guard.hpp` это не
  потребовало — сбой окна до кадрового обработчика не доходит, векторный отвечает раньше
  (кейс `Hook.FaultStillReachesSehWhileHooked`). Потребовало предупреждения: всякий, кто
  добавит сюда свой векторный обработчик, обязан знать, что повторный сбой по одному
  адресу здесь — норма, а не зацикливание. Проверено дорого.

  Потолок апстрима — список страниц, отравленных врезкой, safetyhook не чистит, и сбой на
  такой странице после снятия врезки повторялся бы вечно — закрыт заплаткой, см.
  «Исправлено»: снятая врезка больше не оставляет ловушки на чужой сбой.

  Альтернатива — свой слой ОС с заморозкой потоков — была написана и убрана: четыреста
  строк своего кода, форк чужого файла, врезка дороже в две с половиной тысячи раз, и на
  стресс-тесте она падала так же, как штатная механика.

  Цена: `hid.dll` 622 -> 977 КБ — таблицы декодера Zydis.

- **`graft/watch.hpp` — кто пишет в эту память.** Аппаратная точка останова на запись
  (`DR0..DR3`) с обратными адресами пишущего, прямо из плагина. Врезка отвечает только там,
  где функцию уже знаешь, а поллинг из тика говорит «стало другим», но не говорит кем;
  процессор ловит запись сам, в момент записи, без цены для остальной памяти. Ею найдена
  цепочка «удаление активности -> `vtable[7]` -> сброс путь-агента -> очистка пути» —
  дверь, снаружи выглядевшая как «маршрут иногда пропадает сам».

  **Это инструмент разбора, а не часть библиотеки**: заголовок целиком `inline`,
  `native.hpp` его не тянет, ни одна цель сборки его не компилирует, в `hid.dll` он не
  попадает ни байтом. Пять правил, каждое ценой прогона (регистры ставит чужой поток; адрес
  кратен длине, иначе точка молчит; ловушка поднимается ПОСЛЕ записи; обработчик выходит по
  коду исключения первой строкой; печатать цепочками, а не срабатываниями) — в
  [RESEARCH/theory/watch.md](RESEARCH/theory/watch.md). Краснеет без игры:
  `tests/watch_test.cpp`, железу всё равно, чья память.

- **Сторонний код в поставке сменился**, см. [THIRD_PARTY.md](THIRD_PARTY.md):
  safetyhook (BSL-1.0), Zydis и Zycore (MIT) вместо MinHook и HDE (BSD-2).

- **`deref_object` быстрее в сто с лишним раз.** Раскладки объекта и обёртки различимы по
  `+8` (дескриптор класса против счётчика ссылок), и спрашивать систему о странице нужно
  только в неоднозначном случае: 174,5 нс → 1,39 нс. Разбор блока из четырёх аргументов
  маршалируемой формы — 360 → 8,1 нс.
- **Зашитый адрес движка красит CI.** `.github/no-addresses.py`: шестнадцатеричная
  константа в 6–7 цифр в коде `SRC/` и `INCLUDE/` (комментарии не в счёт) — ошибка; искать
  от якоря и сверять сигнатурой.
- **`.clang-format`: `IndentExternBlock: NoIndent`.** Единственный `extern "C"` в проекте
  (`abi.h`) написан без отступа, а конфиг требовал обратного.
- **Стресс `Hook.TargetUnderTrafficSurvivesInstallAndRemoval` — только по `GRAFT_STRESS=1`.**
  Он переписывает пролог под живым трафиком — это вне контракта врезки, и исход решает
  планировщик: на раннере CI кейс падал с SegFault, локально — в нескольких процентах
  прогонов. Обязательной проверкой такой кейс быть не может.
- **`RESEARCH/` разнесён по темам** в `theory/` (ABI, падения, кадр, дефайны, точка
  останова), а `RESEARCH/scripts/pe.py` разбирает PE без IDA — дизассемблер, импорты и
  ссылки на обычном Python с capstone.

### Исправлено

- **`Method not linked` на каждый метод класса, объявленного самим модом.** Методы
  `class CreatureAI` из `3_Game` мода откладывались (класса на старте нет) и повторялись в
  конце слоя — а движок к тому моменту уже слинковал модуль и писал предупреждение на
  каждый. Регистрации нативов идут ДО разбора модуля, поэтому ни одна граница слоя не
  попадает между разбором и проверкой. Теперь проверка линковки — событие движка
  (`stage::on_link`), и отложенные повторяются на нём. Хост находит её по строке
  `Method not linked '%s.%s'`, начало функции — по `.pdata` (`scan::function_referencing`).
  Регистрации, сделанные подписчиками событий, больше не открывают фальшивый слой.
- **`lea r8..r15,[rip+строка]` не находился при разборе `CfgMods`.** `find_rip_lea` в
  `SRC/graft/defines.cpp` сверял префикс REX целиком (`0x48`), поэтому половина регистров —
  ровно та, у которой поднят бит R, — проходила мимо. Собственный комментарий функции обещал
  обратное («каким бы ни был регистр-приёмник»). Маска на бите R закрывает это по построению.

  На сегодняшней сборке игры дефайны работали: приёмник там из младших восьми. Это была мина,
  а не поломка, — но ровно такая, какую патч игры и взводит.

- **`scan::find_frame_entry` впервые покрыт тестами.** Строки-маяка у этой функции нет,
  поэтому проверялась она только выездом на живую игру, а промах выглядел как «кадровый тик
  просто не работает». Теперь три кейса на синтетическом образе: четыре приметы подряд, отказ
  без маркера `float` (иначе находится одноимённое событие виджета) и отказ, когда цель `call`
  лежит вне кода. Первый же прогон поймал настоящую ошибку в переводе самой функции.

- **Поле-вектор читалось мимо данных.** В слоте поля лежит не сам вектор, а указатель на
  три float (замер — `RESEARCH/theory/abi.md`), и знал об этом один читатель из пяти:
  `obj["m_pos"_f]` отдавал правду, а `field<vector>("m_pos")` — байты указателя,
  истолкованные как координаты. Молча, без падения. Теперь все формы чтения поля идут
  одной дорогой (`read_field`), а писать вектор умеют все три формы `set_field`, а не
  одна: раньше `set_field<"m_pos">(v)` просто не собирался. Паритет форм закреплён
  кейсами `FieldSlots.*` на синтетическом объекте и `Fields_VectorThroughPointer` в игре.

- **Отчёт о падении не был потокобезопасен.** Счётчик, строка последнего сбоя и словарь
  лимитов правились без замка, а сбой приходит с любого потока: детур под защитой
  исполняет тот поток, который пришёл в цель. Два одновременных падения рвали словарь
  прямо внутри обработчика падений.
- **Фильтр исключений обещал то, чего не делал.** Он возвращал «обрабатываем» на любой
  код, включая порчу кучи, и держался только на том, что движок заберёт `0xC0000374`
  раньше. Теперь порча кучи явно уходит дальше по цепочке.
- **Переполнение стека обрабатывалось так, что делало хуже.** Фильтр форматировал строку и
  писал в журнал на том же стеке, который только что кончился, а `_resetstkoflw` не звался
  нигде — страница-сторож не восстанавливалась, и второе переполнение убивало процесс.
  Теперь фильтр только запоминает адрес, а починка стека и отчёт идут из обработчика.
  Кейс ловит два переполнения подряд.
- **Вложенное падение сбрасывало глубину вызовов в ноль.** Арена строк решала, что
  началась новая внешняя цепочка, и прибиралась под ногами у внешнего вызова, который ещё
  жив и держит свои строки. Теперь глубина возвращается на уровень входа.
- **Колбэк `forget` не был защищён** — код плагина звался из движкового пути разрушения
  объекта без обёртки. Теперь обёрнут так же, как нативы.
- **Детур мог уронить игру.** `graft::hook` принимал голый указатель, и код того же
  плагина падал по-разному в зависимости от того, как его позвали. Появилась форма
  `graft::hook<&detour>(target, &orig)` и её пара для пачки `graft::hooked<&detour>(target,
  &orig)`: детур обёрнут защитой, падение отменяет вызов.
  Голая форма оставлена для детуров, которые обязаны досылать управление оригиналу.
- **Врезка под нагрузкой роняла процесс: трамплин освобождался, пока патч только что
  перевёл в него чужой поток.** Закрыто отставкой — снятые врезки выключаются, но больше
  не разрушаются.
- **Снятая врезка перестала оставлять за собой ловушку на чужой сбой.** У safetyhook
  список отравленных страниц не чистится никогда, а обработчик решает по признаку
  «страница когда-то была нашей»: настоящий сбой на ней уходил в вечный повтор вместо
  падения с дампом, и `guard.hpp` до него не доходил вовсе. Признак заменён на
  проверяемый — пока окно патча открыто, поведение апстримное, а после закрытия
  «продолжай» отвечается, только если права страницы подтверждают, что повтор пройдёт.
  Правка живёт заплаткой на зависимость (`SRC/patches`), а не копией файла: подъём версии,
  тронувший тот же кусок, валит конфигурацию с текстом конфликта.
- **В поставке не осталось вызовов, которыми разглядывают чужой процесс.** Ни
  `OpenProcess`, ни `ReadProcessMemory`, ни `WriteProcessMemory`, ни `VirtualAllocEx`, ни
  `SuspendThread`, ни `CreateProcess` — и ни одного их родственника: `hid.dll` больше не
  импортирует ни `CreateToolhelp32Snapshot`, ни `Thread32First`, ни `OpenThread`.


- **Шаблонный класс не собирался вовсе.** `bind.template_class<T>(...).method(...)` строил
  `graft::native` по старому порядку полей — после появления `param_names`/`doc` это
  перестало компилироваться (`cannot initialize ... 'const char *' with an rvalue of type
  'bool'`).
- **`graft::param<"тип">` в маршалируемой сигнатуре не собирался.** Разбор аргумента уходил
  в `value::as<param<...>>`, а в варианте такого типа нет. Наследник `value` теперь читается
  по тегу переменной, как и сам `value`.

ABI: 5, LAYOUT: 2

### Исправлено

- **Хост переехал с `dwmapi.dll` на `hid.dll`.** `dwmapi` нет в таблице импорта ни
  боевого `DayZServer_x64.exe`, ни розничного `DayZ_x64.exe` — она есть только у
  `DayZDiag_x64.exe`. То есть `graft install <каталог сервера>` клал файл, который

  в каталоге игры: в diag импортируются оба имени, и две наши копии в одном процессе

  Сьюта `seraph::graft` переписана под новые имена, поведение и вывод те же.
